# spec/ — 사용자 요구사항, 주제별로, 요구사항만

이 폴더는 **사용자가 말한 요구와 결정**을 주제마다 한 파일에 날짜순으로 모아 두는 곳이다(2026-10-18 사용자 지정: "spec 폴더를 하나 만들고 사용자의 요구사항… 요구사항만을 주제 별로 관리할 수 있도록").
krs-web-agents 의 `spec/spec_<주제>.md`(① 질의·요청 히스토리 ② 확정 사양 ③ 구현 상태 ④ 미결)에서 **①만 떼어 둔 꼴**이다 — 여기에는 요구만 있고, 설계·구현·실측은 다른 문서가 맡는다.

## 무엇을 적나

- **사용자가 한 말과 거기서 나온 결정.** 날짜, 원문(요지나 인용), 결정 한 줄. 왜 그렇게 정했는지가 말에 들어 있으면 함께.
- 뒤집힌 요구도 **지우지 않는다** — 옛 줄 앞에 `(철회 YYYY-MM-DD)` 를 붙이고 새 줄을 더한다. 어떤 요구가 어디서 왔는지 뒤에 알아야 한다.
- 조회성 질문의 답에서 **규칙이 정해졌으면** 그것도 요구다(예: 2026-10-18 "표시 올림은 초과로 보지 않는다").

## 무엇을 적지 않나

- 설계·구조·모듈·선택자·실측값 — `README.md`(동작 설명), `docs/`(설계), 폴더 `README.md`·`CLAUDE.md`(규칙), `rerp/reference.md`(화면 실측), `recipes/`·`actions/spec/`(기계 정본).
- 구현 상태·테스트 결과·미결 — 커밋 메시지와 각 문서.
- 사용자 말 없이 Claude 가 정한 것 — 그건 설계다. 사용자가 "그렇게 해" 라고 했으면 그 말을 적는다.

## 어떻게 쓰나

- 파일 하나 = 주제 하나, 이름은 확장의 탭·갈래를 따른다(아래 목록). 없는 주제면 파일을 만들고 이 목록에 더한다.
- 줄 꼴: `- YYYY-MM-DD — "원문(요지)" → 결정.` 같은 날 여러 건이면 줄을 나눈다. 한 요구가 여러 주제에 걸치면 **주된 주제 하나**에 적고 다른 쪽은 `→ <주제>.md` 한 줄.
- 새 요구가 나오면 **코드보다 먼저** 그 주제 파일에 한 줄 더한다. 요구가 바뀌면 같은 자리에서 철회 표시와 새 줄.
- `README.md`·커밋 메시지의 `(YYYY-MM-DD 사용자 지정: "…")` 인용은 그대로 둔다(동작 설명 옆에 까닭으로 남는 것). 요구의 **원본은 이 폴더**이고, 2026-10-18 이전 것은 그 인용에서 옮겨 적었다 — 아직 옮기지 않은 인용이 있으면 그 주제를 다시 다룰 때 옮긴다.
- `actions/spec/` 은 행위 명세 YAML(기계 정본)이다 — 이 폴더와 다르다.
