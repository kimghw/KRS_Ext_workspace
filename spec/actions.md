# 행위 층 — 사용자 요구사항

사람이 패널에서 누르든 LLM 이 말·문서를 읽어 채우든, 명세(YAML)대로 같은 기록이 되고 그 다음에 실행기가 돈다. 동작 설명은 `actions/README.md`, 규칙은 `actions/CLAUDE.md`, 설계는 `docs/actions-design.md`. 기계 정본은 `actions/spec/<갈래>/<종류>.yaml`(이 폴더와 다른 것).

- 2026-10-16 — "LLM 하고 사람이 클릭을 하면 이게 구조화 된 다음에 러너/실행기를 호출하는 구조로 모두 바꾸고 싶어 … 중간에 yaml 구조파일을 놓고 … 사전설정에 대한 정보도 들어가야 되고, 공문 종류·근태 종류에 따라 각각 yaml 이 존재해야지" → 행위 하나에 YAML 하나(칸마다 인라인 프롬프트 `read` 와 사전설정 `preset`), 기록 → 관문 → 디스패처 → 실행기.
- 2026-10-16 — 범위: "근태·공문·회의실·차량만 하면 됨". R&D 는 "하지 않아도 됨", 기념일 지원은 "하지마" → 그 둘은 옮기지 않는다(명세만 planned). 같은 날 저녁 R&D 의 LLM 작업 둘(뽑기·고치기)은 생겼다 → [rnd.md](rnd.md).
- 2026-10-16 — "반드시 들어가야 하는 거면 빈곳을 찾아갈 수 있는 바로가기 버튼을 넣어줘" → 관문이 막으면 상태줄에 까닭과 함께 빈 곳으로 가는 단추(내 이름·공문 설정·폼의 칸).
- 2026-10-09 — 공문 설정의 채팅 칸은 뺀다("공문안 같이 있어야 하는 거 아닌가?") → 2026-10-16 그 명세(`gongmun.setup`)도 걷어내고 공문 설정은 공문 4종의 사전설정으로.
- 2026-10-17 — "이것도 명세서를 만든 다음에 러너로 실행하도록" (선행 품의 읽기) → 읽기(조회)도 행위로 — 패널이 코드를 직접 부르지 않고 명세 → 기록 → 실행기 → [gongmun.md](gongmun.md).
- 2026-10-17 — 공문 종류 파일의 공통 칸은 갈래 공통(`_domain.yaml`)에만 적고 종류 파일은 가져오기만(같은 글을 다시 적지 않는다).
