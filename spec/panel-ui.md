# 패널 공통 UI 원칙 — 사용자 요구사항

탭을 가리지 않고 되풀이해서 나온 요구. 어느 탭에서 나왔는지는 괄호에.

- 2026-10-15 (메일) — "종료 기능이 없네" · "등록한 메일을 취소하는 기능이 안보임" — 접힌 "관리" 칸 안에 있던 것 → **접힌 칸 뒤에 행위를 두지 않는다.** 항목의 행위는 그 줄·카드에 보이게. 지우기 같은 것은 두 번 누르기 확인으로 충분하고 접어서 숨기지 않는다.
- 2026-10-16 (R&D) — "과제 고치기에 있어야 하는게 아니라 job_id 찾기를 자동으로 하고 여기 페이지에서 맞는지 확인하면 버튼은 사라지고 Jobid 저장만" → **찾을 수 있는 값은 알아서 찾아 보이고, 카드에서 한 번에 저장.** 폼의 찾기 버튼은 두지 않는다. 폼은 손으로 고칠 때만.
- 2026-10-16 (R&D) — "이게 과제 고치기가 뭐냐? 아이콘으로 SSCB 글자 우측에 넣어주던지" · "사람 추가 하는 아이콘을 사람 더하기에 주고, 행정 지원 옆에 설명은 필요 없을 듯" → **제목 줄의 행위는 글 단추가 아니라 아이콘**으로 제목 옆에, 절 제목 옆에 설명문을 두지 않는다.
- 2026-10-16 (R&D) — 손으로 적는 줄도 옆의 생성 표와 같은 모양(글자 크기·표 배치).
- 2026-10-16 (R&D) — "이거 어떤 과제인지 선택이 안되잖아" → 고치는 중인 것의 칩은 켜진 채로 둔다.

- 2026-10-17 (R&D) — "인건비, 공문참조.. 이런 설명은 없어도 될것. 연구자 n명, 행정1명 이렇면 될듯" → **접힌 줄의 요약은 수만**(` · ` 로 이어진 짧은 토큰), 절 제목은 짧게(`A 및 B` 보다 두 글자 이름).

- 2026-10-19 (R&D) — "이것도 주요 변경사항만 보이게 하고 세부적인 것은 접어줘"(변경이력 카드) → **목록의 줄·카드는 핵심(제목·전 → 후)만 펴 두고 긴 설명(사유)은 접힌 한 줄로** — 접힌 줄에는 한 줄로 잘라 보인다. 적는 칸은 접지 않는다 → [rnd.md](rnd.md).
