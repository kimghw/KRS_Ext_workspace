# 출장 여비 — 사용자 요구사항

출장의 여비계산서·사후정산·증빙·여비증빙 송부, 그리고 홈 카드의 출장 줄. 근태 신청 자체는 [attendance.md](attendance.md). 동작 설명은 `README.md` 「근태 탭」 뒤쪽과 「홈 화면의 WORKSPACE 카드」, 규칙 값은 `references/travel-rules.yaml`.

## 홈 카드의 출장 줄

- 2026-10-04 — 홈 카드에 남는 지난 출장은 **여비 정산이 덜 끝난 출장만 다녀온 뒤 4주(또는 8주)까지**. 사후정산을 완료했거나 증빙을 담당자에게 보낸 출장은 올리지 않는다. 몇 주까지는 근태 탭에서 마지막에 누른 값.
- 2026-10-04 — 출장 줄은 여비 증빙을 받는다(끌어 놓기·붙여 넣기). 카드에서 하는 일은 그것뿐이고 예약·근태 조작은 패널에서.
- 2026-10-04 — "올리면 바로 사후등록 하게 해줘, 항공권도 동일하게" → 숙박 증빙·항공권은 넣는 즉시 사후정산에도 올린다(처음엔 보관만 하고 패널 버튼으로 올렸음).
- 2026-10-05 — "홈 줄에서 바로 고르기: 넣은 자리에서 상한액/실제 금액 버튼이 뜹니다. 그리고 상한액의 1.5배는 부서장 승인" → 숙박비가 상한을 넘으면 그 줄에서 상한액/실제 금액을 고르게 하고, 1.5배 이내면 부서장 승인 표시.
- 2026-10-05 — "왜 '사후정산에 올리기' 버튼이 아직 까지 있는 거지? 올리라고" → 보관만 하고 안 올린 증빙은 홈을 열 때 누르지 않아도 올린다. 같은 날 "안올라가서 그 버튼이 있는거면 나두고" → 올려 봤는데 안 됐을 때만 `다시 올리기` 버튼.
- 2026-10-05 — "알림 끄거나 보거나 제거 하는 기능이 안보임" → 끝난 일의 알림은 접고 펴고 지울 수 있다. 잘된 일은 접혀서, 알릴 것이 있는 것은 펴져서.
- 2026-10-05 — "이게 확인이 안되나? 출장이랑 맞잖아" (같은 영수증을 두 번 넣어 버튼이 남음) → 이미 사후정산에 올라가 있는 숙박 줄은 알아보고 다시 묻지 않는다.
- 2026-10-08 — 상한액을 넘겨 실제 금액으로 올리면 비고에 상한 초과 사유가 필수(기본 문구 있음). 패널의 숙박비 내역에서 고쳐 쓴다.

## 사후정산·증빙 (패널 출장 카드)

- 2026-10-05 — 상한액의 1.5배까지는 부서장 승인(홈 줄과 같은 규칙).
- 2026-10-05 — (실제 붙여넣기를 재 보니 PDF 두 장에 읽기 14.7초·서버 3.0초) → 여러 장은 세 장까지 나란히 읽고, 저장·확정 뒤 목록 읽기를 줄인다.
- 2026-10-05 — "여비계산서 상의 값을 기본적으로 갖어오도록 해줘, 갖어온 상태에서 수정을 할 수 있게" → 편의 날짜·시각은 여비계산서에 저장된 값을 보이고 그 자리에서 고친다.
- 2026-10-05 — "저장된 값이 다르면 다른 부분을 확인할 수 있도록" → 저장된 값이 출장 일정·운임표와 다른 편에 `다름 N` 표시.
- 2026-10-05 — "파일올라가면 다 자동 저장인거고" · "보내기 하면 그때 '확정' 하고 보내라고" → 저장만·확정만 하는 버튼은 없다. 증빙을 넣으면 저장, 확정은 보낼 때.
- 2026-10-08 — "수정 가능하게 해줘" → 비고의 상한 초과 사유는 줄을 펴서 고쳐 쓸 수 있다. 사유는 상한액/실제 금액을 바꿀 때 같이 오간다.
- 2026-10-08 — "여기도 웹페이지 카피 공문처럼 하게해줘.. 2개 동일한 기능으로" → 증빙 넣는 곳에 공문 탭과 같은 웹페이지 캡처 단추 둘(전체·부분).
- 2026-10-16 — "증빙/공문 첨부도 api 에서 할 수 있게" → 증빙 글자 먼저 뽑기는 API 키 길에서도 같다 → [settings.md](settings.md).

## 여비증빙 송부

- 2026-10-04 — 칸 이름은 `여비증빙 송부`(여비계산서와 증빙을 같이 보내므로 `증빙 송부` 가 아니다).
- 2026-10-04 — "사전정산 있으니.. 작성할게 없으면 그걸 보내면 됨" → 숙박·비행기 출장은 보관한 증빙이 없어도 여비계산서 출력만으로 보낸다. 당일 출장은 당일증빙이 있어야.
- 2026-10-04 — "확정한 다음에 출력해서 증빙들과 합쳐서 보내야지" → 묶는 PDF 의 맨 앞은 확정한 여비계산서의 출력.
- 2026-10-04 — 보내기는 팝업으로 확인(받는 사람·과제·계정·길·제목·본문). 저장·확정부터 한다는 안내는 팝업에만, 카드에는 적지 않는다.
- 2026-10-04 — 이전에 보낸 곳 세 줄(과제·계정·받는 사람·길 한 세트), 직접 고르는 칸은 접힘 — 보통 같은 과제는 같은 사람에게 같은 길로 간다.
- 2026-10-04 — 보내는 길(Teams · 쪽지)은 칩으로 고르고 기억한다.
- 2026-10-05 — "보내기 이력에서.. 이력을 삭제할 수도 있으면 좋겠어" → 이전에 보낸 곳·보낸 기록에 `×`. 패널이 기억한 것만 지운다(보낸 것이 취소되지는 않는다).
